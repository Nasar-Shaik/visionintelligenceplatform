# Real CCTV / NVR validation — what was done, and what was not

P-5.6 asked for playback validation against Hikvision, Dahua, CP Plus, UNV, generic ONVIF devices,
RTSP streams and NVR recorded playback. This file states plainly which of that happened.

## ⚠️ No surveillance hardware was available, and none was simulated

**No Hikvision, Dahua, CP Plus, UNV or ONVIF device was tested. No NVR was tested. No RTSP stream
was tested.** There is no such equipment on this machine and none reachable from it. Nothing below
should be read as a claim about any vendor's output.

Standing in for it would have been worse than skipping it: a fixture named `hikvision.mp4` that was
actually generated by a browser would put a vendor's name against behaviour that vendor never
produced, and the first person to trust it would be the one deciding whether a customer's cameras
are supported.

## ⚠️ RTSP is not a browser format, and no amount of testing changes that

This is the load-bearing fact and it is architectural, not a gap in coverage.

**No browser plays RTSP.** Not Chrome, not Safari, not Firefox, not Edge — there is no RTSP stack in
any of them and there is no plugin story left. A camera's `rtsp://` URL cannot be handed to a
`<video>` element under any circumstances. Browser playback of live camera video requires the stream
to be transcoded or repackaged server-side into something a browser does speak — HLS, LL-HLS, DASH,
WebRTC or fragmented MP4 over WebSocket — and **this platform has no such component**. The media
service ingests; nothing republishes.

What that means concretely:

- **Recorded evidence playback works** and is what P-5.5/P-5.6 built: the evidence store holds a
  materialised object, the platform issues a signed URL, the browser plays the file.
- **Live camera playback does not exist**, is not partially built, and is not a matter of testing.
  The workspace reports live view as `not-built` rather than showing a broken player.
- **NVR-recorded playback** — asking a Hikvision or Dahua NVR to seek within its own archive over
  its own protocol — is likewise a server-side integration that does not exist. What the platform
  can play back is what it has already ingested.

Anyone reading "playback is production-ready" should read it as _recorded evidence playback is
production-ready_.

## What was validated instead, and how far it carries

Real media was generated locally (Chromium `MediaRecorder`; no system ffmpeg is available) and
decoded in five engines. Full results in [BROWSER_MATRIX.md](BROWSER_MATRIX.md).

| Requested                                 | Status                       | Notes                                                                                                                                                                                                                                                              |

Codec probe verified against all five.                                                                                                                                                                                        |

## What would make this real

In rough order of how much each buys:

1. **One real NVR export per vendor**, checked into a fixture store — Hikvision and Dahua alone
   cover most of the installed base. Container and codec quirks (proprietary `.dav`, non-standard
   MP4 brands, HEVC-by-default) are exactly what the codec matrix cannot predict.
2. **A repackaging component** if live view is ever wanted. That is a service-sized decision and an
   ADR, not a milestone task.
3. **A degraded-network harness** — throttled and flapping links against real files — to exercise
   the network classification path end to end.

None of these were in scope for P-5.6 and none are started.
