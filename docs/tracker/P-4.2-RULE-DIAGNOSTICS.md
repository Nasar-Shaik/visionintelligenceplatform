# P-4.2 — The Rule Support Surface & the P-5 Contract

**Status:** ✅ **ACCEPTED** (Architect, 2026-08-03) — the architecture validation pass was accepted and its six findings became the [P-5 entry criteria](P-5-ENTRY-CRITERIA.md)
**Authorized:** 2026-08-03 (Architect, P-4.1 approval + 15 recommendations)
**Layer:** Product Capability — composition over the frozen foundations, redesigning none of them.

---

## What this is for

P-4.1 built the diagnostic **pieces**. This builds the **artifact**: one download for support, one
verdict for an operator, one diff for a reviewer, one contract for P-5.

The failure it fixes is unglamorous and real — a support engineer gathering six endpoints by hand at
2 a.m., which is to say not gathering them.

**Nothing added here is read during evaluation**, and nothing here may become so.

## The nine decisions

Recorded in full in [ADR-0028](../adr/ADR-0028-rule-support-surface-and-the-p5-contract.md).

1. **One artifact, composed** — absent, not zeroed, where the node does not know. No invented trace.
2. **A score that can be taken apart, or no score at all** — `unknown` beats a confident guess.
3. **Complexity is relative to the deployment**, and bands on the **worst** dimension.
4. **Dependency status is opt-in**, and `unknown` is a real answer.
5. **History is a shift, not a time series** — Prometheus already does that properly.
6. **A diff over snapshots**, conditions compared as a set of leaves.
7. **The plane split is structural; no path moved.**
8. **An incompatible package imports nothing**; name conflicts skip by default.
9. **The P-5 contract is a projection, frozen now** — answering for the version the incident was
   raised by.

## ⚠️ Where I did not do what was asked

Three, each recorded with its reason.

| Recommendation                                         | What was built instead                                                                                                                                                                                                                 |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **9 — separate Authoring / Operations / Runtime APIs** | Separated the **modules**, not the URLs. Prefixing published routes breaks every consumer and integration for a naming improvement ([CONSTRAINTS §41](../project/CONSTRAINTS.md)). A test asserts every published path still resolves. |
| **7 — runtime statistics history**                     | A bounded 24-hour, single-node ring — explicitly _not_ a time series. Prometheus stores history properly; a second, worse one would be permanent.                                                                                      |
| **12 / 15 — freeze the interfaces P-5 consumes**       | Done, with **one gap named rather than papered over**: a per-event explanation trace needs the event, which lives in the Events context. See the validation pass.                                                                      |

## P-5 architecture validation

The Architect's closing instruction was a validation pass before P-5. It is
[P-5-ARCHITECTURE-VALIDATION](P-5-ARCHITECTURE-VALIDATION.md), and its verdict is:

> **No frozen foundation needs to change. Six gaps exist, all in contexts that are not frozen, and P-5
> cannot start until they are approved.**

⚠️ The one that blocks a flagship P-5 feature: **an event cannot be fetched by id.** The investigation
workspace shows why a rule fired; that needs the triggering event; `EventQuery` has no `id` filter and
there is no `GET /events/:id`. Additive, in the Events context, and needed before P-5 starts.

One gap is classified as **technical debt** rather than enhancement: the Workflow context has no index
for the incident searches P-5 will add, and no index-coverage test to catch that (**TD-22**).

## Future Extension

Documented, none built: behaviour and composite dependency kinds · cluster-wide statistics aggregation ·
configurable per-deployment `RuleLimits` (the contract takes them; only the defaults are wired) ·
signed packages · replay simulation over stored history.

## Out of Scope

A rule marketplace · cross-tenant packages · automatic id remapping on import · a diagnostics store.

## Known Limitation

`RuleStatsHistory` covers **one node and one day**, is lost on restart, and attributes everything in a
gap between rolls to the first bucket of that gap. Stated in the contract, not discovered.

## Technical Debt

**[TD-21](../../tracking/TECH-DEBT.md)** — the rule editor cannot be saved in edit mode. Unchanged and
still open; reproducing it in a browser remains step one.
**[TD-22](../../tracking/TECH-DEBT.md)** — new: the Workflow context has no index coverage for the
incident queries P-5 needs, and no coverage test.
