- **AI-5d Health Monitoring, Auto-Recovery & Model Lifecycle ✅ code+tests complete, ⏳ awaiting review** (plan approved + 8 further recommendations; **17 recommendations total** folded in). **In `ai/inference`, no new service; frozen five untouched; no new architectural layer** — AI-5d _supervises_ stages that already exist. AI-5b made a session survive its **camera**, AI-5c its **neighbours**; AI-5d makes it survive **itself over time**. **`HealthMonitor`** replaces the healthy/unhealthy bit with a **0–100 score decomposed across connection · inference · scheduler · resources · recovery** (every component **required** in the output — a report that omits a subsystem is the one that misdirects an operator), each indicator carrying a `Trend` so health reports where it is **heading**; a projected decline becomes one more pressure reason on the governor's existing path, because **health decides nothing** — two components able to degrade a session independently is how you get undebuggable oscillation. **`AutoRecovery`** **executes the frozen AI-5b taxonomy** within a **budget expressed as configuration**: retail 3 restarts · factory 10 · bank unlimited-with-long-cooldown · **healthcare never auto-restarts** — all four shipped as deployment profiles; `configuration` failures are **never retried**, enforced as a code-level invariant that _rejects_ a profile asking for it. **`RecoveryReason`** records trigger · subsystem · severity · retry count · correlation id, and **every refusal is recorded too**. **Progressive restoration** replaces ladder reversal: each degradation pushes a **`RestoreStep`** recording exactly what it removed and each recovery pops it, making exact-reverse restoration **structural rather than intended**. **Anti-oscillation** is **direction-aware** — a reversal waits out a stabilization window, but two escalations in a row are the ladder doing its job and are never delayed (this correction surfaced when a naive guard broke two existing scheduler tests). **`ModelLifecycleManager`** stages every version change `warming → validating → switching → draining → active` with rollback on the same mechanism run backwards; zero downtime rests on one indirection — the analyzer holds a **`ModelSlot`** read **per frame**, so promotion is an attribute assignment and no session stops. - **AI-5e Production Certification Framework ✅ code+tests complete, ⏳ awaiting review** — the **final milestone of AI Runtime Architecture v1.0** and, per the Architect, the **last AI runtime milestone (no AI-6)**. Explicitly redefined by the Architect: _"The software can build the framework. Real hardware validates the framework"_ — and re-prioritized so **accuracy on recorded CCTV footage outranks hardware certification**. **In `ai/inference`, no new service, no new layer; frozen five untouched.** The organising idea is **`EvidenceClass`** (`simulated` → `recorded-footage` → `hardware`) threaded through every check, report and promotion, with three rules made **structural rather than conventional**: a report is only as strong as its **weakest** check; **`certified` is unreachable without `hardware`**; **`production` maturity is unreachable without `hardware`**. A complete run against a simulated source — every check green — still returns `pending-validation`, and a **negative control** asserts it, because a framework that can certify itself from its own simulations converts a known unknown into a false assurance someone will quote to a customer. - **P-5.6 Playback production verification ✅ code+tests+UI complete, ⏳ awaiting review** — a verification milestone, not a feature one: browser validation, touch, memory, recovery, real media. The stored codec name is now _translated_ into representative RFC 6381 candidates (§86b), and `hvc1`/`hev1` are both tried because Safari accepts one and refuses the other. ⚠️ **A positive probe is not a promise** — WebKit and Safari answer `probably` to `avc1.42E01E` and then reject a real H.264 file, so the check may refuse and may never promise (§87). ⚠️ **The most consequential finding: a truncated or corrupted recording plays with no error event in any engine**, reporting half the duration — the platform now compares where the playhead stopped against the duration the record declares and states the shortfall persistently (§88). ⚠️ **The leak was bandwidth, not memory**: 13.33 MB against 1.61 MB over 60 clips opened and closed, while heap and node counts were indistinguishable.
